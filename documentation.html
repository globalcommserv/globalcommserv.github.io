Website handover guide

GCS Website Documentation

By Runell Ricks Jr.Published August 27 2026

This documentation details the technology stack and means of deployment of the website globalcommserv.com, accessible at https://globalcommserv.com/. This is intended as a basic handover document to be read by employees of Global Commerce and Services LLC, and is not wholly inclusive documentation on Github, GitHub Pages, GoDaddy, or the website codebase of globalcommserv.com.

Codebase

The website uses an AI-generated codebase ideated by Mr. David Shephard, using an unknown AI model. Due to the codebase being AI-generated, much of its syntax and organization are round-about and redundant - these qualities must be taken into account when hand-modifying webpages. Many webpage elements are nested in multiple layers of wrapped elements, which increases complexity as to which specific elements are affected by which CSS properties.

The codebase uses no external libraries or frameworks, and simply uses the standard CSS and JS functionality as defined within the project files. The website's associated .css stylesheets and .js script are all located at the project root, alongside the .html webpages and other assets.

Additionally, each .html webpage is written and defined individually. The website codebases do not use any standardized partials, and every facet of the webpage (header, footer, menus, etc.) are defined bespoke within each .html file.

The project includes two code partials, header.html and footer.html, but neither partials are invoked in any .html webpage. These were made as part of an experiment to introduce partials into the codebase, but these efforts were unsuccessful, and the partials were left in case future efforts are made.

The website codebase is, conceptually, simple and straightforward. Everything is defined at the project root with no subfolders or other directories, and everything is self-contained; there are no libraries, partials, or overhead. While this makes modifications brutally straightforward, it also does not leverage time-saving frameworks like tailwindcss or reactjs.

Due to the very decentralized nature of the project's files and functionality, it's recommended to use another AI model to read and write into the codebase to better modify the motley of project folders. It is also recommended for a human developer to streamline and truncate codebase when applicable, to increase human legibility of codebase.

Files & Asset Placement

All of the webpages, including the homepage “index.html” are all parented to the project itself - i.e. they are not contained in any subfolders. Neither are the site resources located in any subfolders, and are also parented to the root, sibling to the webpage .html files themselves.

This simplified layout that globalcommserv.com uses is important to consider, as all asset references invoked within the webpage files are relative to each file - i.e. calls upon sibling assets. An .html file calls upon an image that is located adjacent to the .html file itself, or calls upon a stylesheet adjacent to the .html file itself. If that image or stylesheet was stored in a sub-folder, the webpage will break.

So, if any additional images or assets were to be added, they should be added directly to the project root, alongside all the other current files. Nor should any present assets be moved, lest drastic changes should be made to every content element within each .html webpage.

Hosting & Version Control

Github Pages is the means of website hosting and version control. Github is a software development service and pseudo-cloud storage provider. The service uses Git, a version control system that tracks all changes in a software project. Git is useful for tracking various changes in a project, and allows developers to rollback changes or merge different versions together.

The website codebase for globalcommserv.com is uploaded as a repository to Github, accessible at https://github.com/globalcommserv/globalcommserv.github.io. And, as a repository, its entire history of changes is tracked by Git. This makes it easy to rollback changes and revert to a previous build, which is useful when encountering errors or conducting troubleshooting.

Additionally, Github offers a service to deploy repositories as live websites called Github Pages. This is the means that globalcommserv.com is currently published.

Tangentially, the aforementioned layout of files and assets are important to the context of Github Pages. Because index.html and associated .html files are defined at the root (i.e. immediately in the repository and not in subsequent folders), the website can be deployed from the project root or repository root.

This is an important navigational distinction, as different websites have different layouts for their organization of assets and resources. Many Github Pages websites house their assets (images, cascading stylesheets, and javascripts) into subfolders; others may deploy from subfolders entirely (ex. The “/docs” directory), which can be configured in the Pages section of the repository settings.

However, the largest concern to note is that the website repository of public on Github. Github Pages are free for public repositories, but to public repositories are open for all users to fork, clone, and modify for their own use. Though the main globalcommserv.github.io repository itself cannot be modified by anyone, it does mean that anyone can clone the website code and create impostor websites.

The easiest remedy is to simply make the repository private. However, this would disable the Github Pages deployment without a GitHub subscription plan, like Pro or Enterprise. Thus, the easiest remedy will require purchasing a subscription.

Domain

The website is reachable through two URLs: globalcommserv.github.io and globalcommserv.com.

“.github.io” Domain

globalcommserv.github.io is, as denoted by the domain, the default URL provided by Github Pages itself. This default URL provided by Pages is typically a subdomain parented to the user or organization that owns the repository. For example, the prototype website was stored in the repository “gcs_proto3” which is owned by Github user ricks4, hence the URL provided by Github Pages is rricks4.github.io/gcs_proto3. However, because the repository of the globalcommserv website is itself called globalcommserv.github.io (https://github.com/globalcommserv/globalcommserv.github.io), and owned by the Github organization “globalcommserv”, the default URL is thusly globalcommserv.github.io.

“.com” Domain

In contrast, the domain globalcommserv.com is provided by a third-party: GoDaddy.

GoDaddy is an online domain provider and website builder. This was the service that formally hosted the original globalcommserv.com website, which used the archaic GoDaddy website builder using the Website+Marketing plan. The old website is no longer in use, and the domain instead routes to content hosted at globalcommserv.github.io.

This is accomplished through changing the domain's DNS configuration. This can be found within the globalcommserv.com product page, under the “Domain” submenu, going under the “DNS” tab, then looking under the “DNS Records” section. This section lists the various DNS configurations associated with globalcommserv.com.

The configurations that link the globalcommserv.com domain to the website hosted at Github Pages are the following entries:

TypeHostPoints to
A@185.199.108.153
A@185.199.109.153
A@185.199.110.153
A@185.199.111.153
CNAMEwwwglobalcommserv.github.io

Note that these records are scattered amongst all the other pre-existing DNS records. The four “A” type records reference IP addresses to Github, whilst the “CNAME” type record references the default Github Pages domain for the GCS website.

It is not recommended to edit these records, as they are vital to guarantee the DNS connection between the GoDaddy domain and the Github Pages website content.

However, within the GoDaddy products page accessed by Mrs. Joaneane Smith, the globalcommserv.com domain should NOT be mistaken for the “Global Comm Serv” website (globalcommserv.godaddysites.com). The latter product, “Global Comm Serv”, is a website using GoDaddy's new website framework, not connected to the globalcommserv.com domain.

In Closing

Although topically complicated and spread out across two services doing three different things, the technologies behind the new globalcommserv.com website are fairly simple. It just uses two third-parties - Github and GoDaddy - that manage everything. Github holds the code, GoDaddy holds the .com domain. That's it. All other functionality branches from there.
